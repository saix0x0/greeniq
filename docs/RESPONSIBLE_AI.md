# Responsible AI note (submission artifact H)

> Numbers quoted here are generated by code: [`reports/EVALUATION.md`](../reports/EVALUATION.md),
> [`reports/GROUNDING.md`](../reports/GROUNDING.md), [`reports/EDGE_CASES.md`](../reports/EDGE_CASES.md).

## Privacy
- **No real personal or customer data.** Every home, meter reading and sale is generated by a
  documented, seeded simulator ([`data/DATA_CARD.md`](../data/DATA_CARD.md)). There are no names,
  addresses or postcodes.
- The optional language model receives only a compact fact sheet about one (synthetic) home: numbers
  and labels, with no identifiers beyond an internal property ID. With no key configured, nothing
  leaves the machine.
- Customer constraints ("no heat pump", "already did the loft") are per-request inputs and are not
  stored by default.

## Bias and fairness
- **Size.** PS2 forbids calling a home inefficient just because it is big. Intensity is per m², and
  improvement potential is a percentage of each home's own use. The ranking's correlation with floor
  area (0.54) is close to the true potential's own (0.47), whereas ranking by total kWh is 0.76.
  `reports/EVALUATION.md` §4 has the details.
- **Property type.** Model error is reported per type, because some types are served worse. Median
  absolute % error of the electricity model ranges from 17.8% (flats) to 27.0% (bungalows). That
  disparity is disclosed, not hidden.
- **Feature choice.** No socio-economic or demographic features are used (no deprivation index, no
  occupant data). Models see only physical characteristics recorded for the home.
- **Data skew.** The synthetic stock skews older than England's (more EPC D/E than the national
  register), which gives the ranking task enough poor homes. Results may not transfer to a newer stock.

## Explainability
- The score is a fixed weighted sum. Every component shows its input, sub-score, weight and
  contribution, and every number in the UI opens a **receipt** (inputs, method, version, source).
- Every input is tagged **observed / derived / assumed / estimated / missing**, so the UI never
  presents an assumption as a measurement.
- Each Next Best Action carries exactly **three reasons**, each linked to the fact it rests on.
- Savings are shown per fuel, standalone and in sequence, with the interaction made explicit
  ("separately 13,230 kWh, together 10,320 kWh").

## Hallucination
- **Code computes, language explains.** The language model never produces a number that reaches
  the user. A grounding gate checks each explanation's:
  - numbers and the role each one plays;
  - units;
  - per-fuel direction;
  - value-promise wording;
  - scenario.

  Text that fails is replaced by the deterministic template. On held-out homes the gate:
  - wrongly blocked 0 of 387 honest explanations;
  - caught 187/187 invented numbers, 186/186 flipped directions, 187/187 value promises and 135/135
    off-scenario measures.
- What-if questions are parsed by rules, never by the model, and the engine always reruns first.
- The app is fully usable with the model switched off.

## Human oversight
- Every saving, carbon and value figure is labelled an **estimate**, and value is an **indicative,
  non-causal range**.
- Uncertain cases go to a human, never to a confident number:
  - **Refer for survey** when a key fact is missing or conflicting (e.g. "heat pump" recorded but the
    gas meter shows heating);
  - **unavailable** when a baseline is zero or unmetered;
  - a **score range** when a component cannot be assessed.
- GreenIQ informs a conversation; it does not approve lending or guarantee outcomes. A qualified
  assessor should confirm any measure before work begins.
- Data conflicts are surfaced and lower confidence; they are never silently resolved. Planted wrong
  heating records were detected 22 of 24 times, with 0 false alarms.

## Data limitations
- **Synthetic data.** Agreement with the simulated world shows the pipeline works; it is **not**
  evidence of real-world accuracy. Every report says so.
- The engine and the simulator share well-established physics (heat loss, degree days). Hidden
  behaviour, installation quality and record errors keep the evaluation honest, but some optimism
  remains.
- Value premiums are associations planted from the literature's order of magnitude. The model can
  only rediscover them, so they say nothing about the causal effect of retrofitting.
- Emission factors are DESNZ 2025 annual averages (the electricity factor is derived from DESNZ's
  published 15% change; see `greeniq/config/emission_factors.json`). The marginal emissions of extra
  winter demand can differ.
- Costs are indicative ranges from secondary sources, not quotes, and grant eligibility is not
  assessed.
